### 四层责任图

依赖单向流向组合入口：

```text
Execution Host → SpecCraft Domain → Shared Kernel → Contract
                         └────────────────────────→ Contract
```

| 层 | 负责 | 禁止负责 |
| --- | --- | --- |
| Contract | 定义跨模块稳定的数据结构、标识、状态词汇和序列化约束；为消费者提供同一公开协议 | 不编排流程、不保存状态、不调用模型、不批准产物、不包含宿主实现 |
| Shared Kernel | 提供可复用的 Run 生命周期、命令校验/状态转换、审批与产物关联等通用机制；维护确定性不变量 | 不包含 SpecCraft 的产品规则，不解释需求，不决定内容质量，不替用户批准 |
| SpecCraft Domain | 定义八阶段的领域语义、产品规则、阶段门、产物含义及从需求到 PRD/TD/DeliverySpec 的领域流程 | 不承担 HTTP/CLI/UI 适配，不直接依赖具体模型或数据库，不改变已批准 PRD |
| Execution Host | 组合并调用领域能力；承接 HTTP、CLI、Worker 或 Codex 等入口和外部适配；把后端结果投影给调用者 | 不复制领域规则，不自行推导状态，不成为事实源，不越过 Gate 或代替用户批准 |

Contract 是共享边界；Kernel 依赖 Contract；SpecCraft Domain 依赖 Contract 与 Kernel；Execution Host 负责组合并调用领域能力。具体适配器和持久化尚未实现，不能由该图推断它们已经存在。

### 核心对象词典

下表是目标语义，不是当前代码对象清单。除来源样例和静态 API 投影外，运行时对象目前均不存在。

| 对象 | 定义与权威性 | 分类 | 当前状态 |
| --- | --- | --- | --- |
| Source | 输入材料的身份、类型、位置与来源信息；提供证据出处，原文不自动成为确认事实 | 外部证据来源 | 仅有匿名文件样例，无运行时 Source |
| Fact | 关于需求/仓库的可追溯陈述；必须保留来源与确认状态，未经确认的候选不得伪装成已确认事实 | 领域事实 | 无 Fact Ledger |
| Decision | 用户对产品或技术选项作出的选择及其理由/来源；是具有责任主体的决策记录 | 事实与决策历史 | 无运行时 Decision |
| Run | 一次 SpecCraft 工作的身份、当前阶段和生命周期状态；状态以领域/内核事实为准 | 流程事实 | 不存在 |
| Artifact | 有类型、内容和版本身份的正式或候选产物；批准必须绑定明确版本 | 产物事实及修订历史 | 不存在 |
| Approval | 用户对指定产物版本作出的批准或拒绝及时间/主体记录；不得由模型产生 | 控制事件历史 | 不存在 |
| Snapshot | 某时点对相关状态的可读快照，用于观察/传输；它是投影，不能反向覆盖事实源 | 投影/观察 | 不存在 |
| Checkpoint | 为恢复执行而记录的必要进度和恢复数据；恢复时仍须校验其与事实源的一致性 | 恢复状态 | 不存在 |

Source 是证据入口，不等同于 Fact；Decision 和 Approval 记录由谁确认了什么；Snapshot 是读取投影；Checkpoint 只辅助恢复。后续实现必须明确各自事实源，不能以页面状态、模型文本或快照取代它们。

### 八阶段产品契约

名称和顺序与当前 `/api/scaffold` 响应一致。控制者描述目标产品责任，不表示脚手架已有阶段执行能力。

| 阶段 | 输入 | 输出 | 控制者 | 暂停条件 | 完成证据 |
| --- | --- | --- | --- | --- | --- |
| 需求上下文构建 | 用户需求、授权的来源及只读仓库上下文 | 带出处的 Source 与有限上下文切片 | 用户提供/授权；代码校验路径、权限与边界；模型可协助摘要 | 来源缺失、越权、路径不安全或上下文不足 | 来源清单、规范化位置、读取结果及内容标识；当前阶段尚无此类记录 |
| 需求澄清与决策 | 已构建的上下文、已知事实与缺口 | 澄清问题、用户回答、Decision 和确认状态的 Fact | 模型可提出问题/候选；代码记录并校验；用户确认事实与决策 | 关键事实冲突、缺口未答或用户尚未决策 | 可追溯到来源及回答的决策记录；当前阶段尚无此能力 |
| 产品规格设计 | 已确认的产品事实与领域编制规则 | PRD 草稿及其来源/版本关联 | 模型可起草；代码校验结构与追溯关系；用户保留修改权 | 关键事实未确认、草稿结构不合格或发现冲突 | 可读取的 PRD 候选及对应事实/规则引用；不是批准证据 |
| 产品规格验收 | PRD 草稿、确认事实和问题清单 | 经人工修订并批准冻结的 PRD 版本，或待修改状态 | 用户批准；代码验证 Gate 并记录精确版本；模型不得批准 | 必需内容缺失、事实矛盾、版本变化或用户未批准 | 指向确定 PRD 版本的 Approval 记录；当前不存在 |
| 技术方案设计 | 已批准冻结的 PRD、目标仓库工程约束 | TD 草稿及设计依据 | 模型可提出方案；代码校验输入 Gate/结构；用户掌握技术取舍 | PRD 未批准、技术约束冲突或关键选择待用户决策 | 可追溯至冻结 PRD 的 TD 候选；不得回写 PRD |
| 技术方案验证 | TD 草稿、工程约束、确定性检查和审查结果 | 验证发现、修订候选及收敛证据 | 代码执行确定性规则；模型可提出审查发现/修订建议；用户处理取舍 | 硬规则失败、问题未处理、修订造成回归或证据不完整 | 检查结果、问题处置及针对候选版本的验证记录；当前无质量闭环 |
| 技术方案验收 | 已验证 TD 及明确的版本/问题状态 | 用户批准的 TD 版本，或退回修订 | 用户批准；代码验证 Gate 并记录版本；模型不得批准 | 硬问题未解决、版本与验证证据不匹配或用户未批准 | 绑定具体 TD 版本的 Approval 记录；当前不存在 |
| 交付物发布 | 已批准 PRD、已批准 TD 及关联信息 | PRD.md、TD.md、DeliverySpec.json 的一致发布集合 | 用户发起/确认发布；代码检查引用一致性并执行发布；模型不能宣布发布成功 | 任一审批缺失、版本引用不一致或产物校验失败 | 三项交付物的版本/内容标识及发布结果；当前未实现 |

全程控制权规则：模型只能给出候选；确定性代码负责规则校验和合法状态转换；产品/技术决策及 PRD、TD、发布批准权属于用户。遇到“让模型自动批准 PRD”，应拒绝该状态转换，并指出用户是批准责任者、代码只负责 Gate 和记录。

### 控制权表

| 行为 | 模型 | 确定性代码 | 用户 |
| --- | --- | --- | --- |
| 解释材料、提出问题/选项、起草 PRD/TD | 可提供候选 | 校验输入/输出结构并记录来源 | 提供材料、回答问题、修订内容 |
| 确认需求事实与产品/技术取舍 | 可提出建议，不得确认 | 校验授权、保存 Decision/Fact 及来源 | 唯一决策者 |
| 改变 Run 状态、执行 Gate | 不得直接改变 | 唯一合法状态转换执行者；条件不满足时拒绝 | 可发起被允许的命令，不得绕过 Gate |
| 批准 PRD、批准 TD、批准发布 | 禁止 | 校验对象/版本、记录批准主体，不得代批 | 唯一批准者 |
| 宣告完成或恢复 | 不能以自然语言作为证据 | 依据持久/当前状态和可复现证据返回结果 | 检查证据并作出批准/决策 |

### 阶段 01 最小接口草案（冻结语义，字段仍由阶段 01 合同测试确认）

阶段 01 可在 FastAPI 中增加创建、读取 Run 与独立审批命令。阶段 00 不添加这些接口。

| 操作 | 最小请求 | 最小响应/结果 | 失败语义 |
| --- | --- | --- | --- |
| 创建 Run | `POST /api/runs`，包含非空原始需求文本 | 服务端生成的 Run 标识、当前状态及 PRD 草稿摘要 | 请求无效时返回明确客户端错误；不创建部分 Run |
| 读取 Run | `GET /api/runs/{run_id}` | 后端权威状态、可用产物摘要及审批状态 | 未知标识返回 Not Found，不伪造成功对象 |
| 批准 PRD | `POST /api/runs/{run_id}/approvals/prd`，由独立用户命令触发并指向被批准的 PRD 草稿版本 | 新 Run 状态、审批记录摘要以及 Gate 后出现的 TD 草稿摘要 | 未找到 Run、PRD 不可批准或版本冲突时拒绝；失败后状态不变 |
| 批准 TD | `POST /api/runs/{run_id}/approvals/td`，由独立用户命令触发并指向被批准的 TD 草稿版本 | 新 Run 状态、审批记录摘要及 Gate 后生成的 DeliverySpec 摘要 | PRD 未批准、TD 不可批准或版本冲突时拒绝；失败后状态不变 |

最小响应必须由服务端返回状态，前端不得推导。错误至少区分无效输入、资源不存在、当前状态禁止操作和版本冲突。阶段 01 允许单进程内存、同步执行和确定性 Fake Provider；不得声称重启可恢复或内容质量已被证明。

阶段 01 明确非目标：SQLite/迁移、LangGraph、真实 Provider、Worker、SSE、自动质量循环、Codex 插件、跨进程恢复。只有阶段 01 获得单独确认后才实现 Run；本阶段没有生产实现或新增依赖。
