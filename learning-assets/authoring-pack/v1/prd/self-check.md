# PRD 提交前自检

在一次提交前完成下面检查；发现问题时由当前 Codex 模型直接修订一次。仅当缺失信息会改变产品范围、角色、核心流程或验收口径时，才向用户澄清。

- [ ] 所有模板章节都已填写，没有 `<...>`、`TODO`、`待补充` 或空白占位。
- [ ] “背景、目标与成功标准”说明了可观察的业务结果。
- [ ] “范围与非目标”明确，并说明了与既有能力需要保持不变的边界。
- [ ] “角色与场景”“功能与核心业务流程”“业务规则与产品边界”和“异常体验与产品规则”完整且互不矛盾。
- [ ] “验收标准”以业务语言描述可验证的前置条件、动作和结果。
- [ ] 正文没有把 API、数据表、技术架构、错误码、性能参数或运维设计伪装成产品需求。
- [ ] “文档信息”没有写入“待审批”“已审批”等生命周期状态；审批事实由 Runtime 快照保存和展示。
- [ ] 没有把未经确认的假设写成业务事实；仍影响范围的假设已转为澄清问题。

将检查结论以简短摘要作为 Evidence 记录；它不是 CLI 内容 Gate，也不能替代用户批准。
