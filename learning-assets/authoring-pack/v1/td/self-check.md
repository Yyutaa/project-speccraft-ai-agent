# TD 提交前自检

在一次提交前完成下面检查；发现问题时由当前 Codex 模型直接修订一次。仅当存在无法从 PRD、仓库事实或安全默认值推导的技术取舍时，才向用户提出技术决策。

- [ ] 所有模板章节已填写；不适用章节明确写出“不适用”和原因，没有占位内容。
- [ ] TD 明确绑定一个已批准 PRD Revision，且没有改变该 PRD 的产品范围或验收承诺。
- [ ] 仓库现状、Harness 规则和改动范围来自实际只读上下文，而不是猜测。
- [ ] 总体架构与端到端流程解释了关键时序、状态与责任边界。
- [ ] API、事件、错误和幂等语义只定义一套，且与前后端、异步流程和失败恢复一致。
- [ ] 数据、状态、事务、并发和外部依赖的关键风险已说明；不适用项有理由。
- [ ] 每项 PRD 验收标准均有对应的验证路径或测试证据。
- [ ] `DeliverySpec.json` 已由当前模型生成，并能通过项目 P0 Schema 校验。
- [ ] “文档信息”没有写入“待审批”“已审批”等生命周期状态；审批事实由 Runtime 快照保存和展示。

将检查结论以简短摘要作为 Evidence 记录；它不是 CLI 内容 Gate，也不能替代用户对 TD 的批准。
